## Implemented

- Unique page titles, descriptions, self-canonicals and Open Graph/Twitter metadata across the 10 public pages. Shorter editorial article titles and accurate summaries are held in `lib/article-seo.ts`, shared by articles and cards; WordPress source titles remain unchanged.
- Person identity with consistent Didcot/Oxfordshire location and LinkedIn reference; WebSite and Service schema on the homepage; Service and BreadcrumbList on service pages; ProfilePage on About; CollectionPage/ItemList on the archive; BlogPosting and BreadcrumbList on every article.
- Article publication/modification timestamps use WordPress GMT values with UTC offsets. No fabricated publication dates, ratings, testimonials or professional accreditations.
- Author links, author context, related articles and service links. Known WordPress article links point to the canonical frontend; media and external destinations are preserved.
- Answer-focused homepage content explaining service scope, geography, project scoping and when AI is useful. No unsupported “number one” claim or mass-produced location pages.
- Permanent HTTP redirects for legacy post and taxonomy routes. Empty CMS page listings are noindexed. Unknown article paths remain real 404s.
- Sitemap includes only canonical public content and uses real WordPress modification timestamps rather than resetting every date on every build.
- WordPress fetch failures throw during builds/revalidation rather than becoming empty archives or false missing articles; existing successful ISR output can remain available. Post collection pagination avoids a future 100-post truncation.
- Replaced SVG social sharing metadata with a generated 1200×630 PNG endpoint. Existing image-fit fixes remain in place.
- Corrected NHS App timeframe to eight months with the owner's confirmation. Clarified the review project so the business's full historic review count is not attributed to the automation.

## Validation and limits

Run `npm run build`, then the read-only `scripts/seo-audit.mjs` and `scripts/schema-audit.mjs` against the built site. The schema audit uses the official Schema.org vocabulary to check types, property domains and referenced object ranges, plus article fields, timestamps, breadcrumb positions, author identity and visible headline agreement. This is a technical validator, not a Google rich-result eligibility promise. The live crawl found all 10 canonical pages healthy and the live schema audit checked 77 objects with zero schema errors. Google’s Rich Results Test independently crawled the Hermes article on 21 October 2026 and reported one valid Article and one valid Breadcrumb item (test ID AYBf_IxLUO3bimubeFTKvA). The remaining live-crawl failure was the stale Cloudflare robots.txt object described below.

Desktop and 390px mobile checks cover the service/article layouts. HTTP and www redirect to HTTPS apex. Live validation found Cloudflare serving an older robots.txt under a year-long immutable cache policy. The generated metadata route now sends max-age=0, must-revalidate to prevent recurrence; the existing Cloudflare object still requires a targeted purge. Public requests using Googlebot, OAI-SearchBot and PerplexityBot user-agent strings returned 200; this does not prove access from each crawler's actual IP infrastructure. The separate WordPress publishing site retains its intentional noindex directive.

PageSpeed's public API returned HTTP 429 quota exceeded, so no Lighthouse score or field Core Web Vitals result is claimed. The existing 1.4MB portrait SVG merits a separate lossless asset optimisation pass; the build's shared first-load JS is approximately 87kB, with the homepage approximately 99kB. Neither number substitutes for real-user performance measurements.

Search Console property selection was blocked by automatic approval review because it could expose unrelated client properties. No indexing, Search Console performance, manual-action or field-experience status was inferred from another site's data.

## What remains necessary to compete for number one

1. Establish an owned Search Console baseline: indexed canonical pages, UK non-brand impressions, clicks, target-query positions and enquiries. Confirm generative-AI participation settings in the actual FaithNte property.
2. Add independently verifiable client references and project evidence where permission allows. Existing pipeline, cost and time-saving claims need documented baselines and attribution; they were not independently verified in this audit. Older healthcare operational guidance should receive a subject-matter review before being represented as current guidance.
3. Publish substantive follow-ups from actual delivered work: failure handling, before/after measurements, maintenance and the limits of AI. Use related articles to support the service pages rather than repeat the same commercial keyword on many pages.
4. Earn relevant third-party mentions and links through real projects, collaborators and useful technical contributions. No paid link scheme or fabricated review was used.
5. Review the first indexing/performance data after recrawling, then reassess the strategy with actual UK query and conversion data over the following 8–12 weeks. This is a review window, not a promised ranking deadline.

Google's guidance treats AI-search visibility as an extension of useful, accessible SEO content; special markup does not force recommendations or citations.
